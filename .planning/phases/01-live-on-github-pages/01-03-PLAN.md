## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| third-party action code to Actions runner | Action repositories run with the job's token and can publish the site |
| Actions runner to GitHub Pages | The job's OIDC token and pages: write permission can replace the live site |
| workflow expression to shell | Step outputs interpolated into run scripts become shell code |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-01-09 | Tampering | the five `uses:` actions (a moved or compromised tag) | high | mitigate | Pin each to a full 40-character commit SHA with a version comment; the structural check rejects any `uses:` without one |
| T-01-10 | Elevation of privilege | GITHUB_TOKEN scope | high | mitigate | Top-level permissions exactly contents read, pages write, id-token write; the structural check asserts the exact mapping (repo default is already read) |
| T-01-11 | Tampering | deploying a build whose tests failed | high | mitigate | `npm test` precedes build, upload and deploy in one job with no `if:` or `continue-on-error` before upload; asserted by the structural check |
| T-01-12 | Tampering | smoke-check step shell script | low | mitigate | page_url reaches the script through env PAGE_URL, never interpolated into the script text; asserted by the structural check |
| T-01-13 | Tampering | deployment from a non-main branch | medium | accept | The github-pages environment already allows only `main` (verified with gh api during research) and the workflow triggers only on push to main and manual dispatch; runs are deployed from main only in plan 01-05 |
| T-01-14 | Information disclosure | secrets in workflow logs | low | accept | The workflow uses no repository secrets; only the automatic OIDC token for Pages |
</threat_model>
