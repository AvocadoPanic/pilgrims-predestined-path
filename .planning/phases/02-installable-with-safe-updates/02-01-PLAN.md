## Phase Goal

**As a** player, **I want to** install the game on my phone or computer and get new versions between games, **so that** it opens like an app and an update never ends a game in progress.

This plan is the phase tracer. Task 1 proves the whole update path end to end (plugin build, worker, registration, controller, setup-screen UI, Start) in a real browser before any expansion. Tasks 2 and 3 expand from that proven slice.

<objective>
A returning player whose browser holds a newer build sees "A new version will load when you start." on the setup screen, and pressing Start loads the new build and starts the game they chose; a game in progress is never reloaded, in this tab or another (PWA-04, D-01 to D-05). The setup footer names the build (D-14). A build test guards the manifest identity and the worker under the base path (SC5, PWA-01 groundwork).

Purpose: every later content phase ships through this worker, so the update path must be right before the first deploy.
Output: vite-plugin-pwa in devDependencies; function-form vite.config.js; src/pwa/updates.js, store.js, startHandoff.js and their tests; main.jsx registration; App.jsx begin/onStart, hint and footer; the PWA block in build-output.test.js.
</objective>
