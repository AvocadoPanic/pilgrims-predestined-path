## Phase Goal

**As a** player, **I want to** install the game on my phone or computer and get new versions between games, **so that** it opens like an app and an update never ends a game in progress.

Gap closure, plan 1 of 2. It closes the one gap in 02-VERIFICATION.md (CR-01: a browser that blocks site storage gets a blank page, a regression of "it opens") and folds in review warning WR-01 (the Start-with-update flow becomes a tested helper with visible progress). Task 1 is the tracer: it proves in a real Edge session with storage blocked that the production build opens and starts a game. Tasks 2 and 3 expand the Start path from that proven slice. UI-SPEC was skipped by the user for this gap closure: no redesign, one new short line in the existing setup style.

<objective>
A player whose browser blocks site storage sees the setup screen and can play, instead of a blank page (CR-01). Pressing Start while an update waits shows "Loading the new version...", ignores extra presses, keeps the pilgrim count fixed, clears its timer on unmount, and always ends with either the new build or a started game, even when the handoff save or the apply call fails (WR-01).

Purpose: the update path added in this phase must never stop the game opening or starting in a browser it opened in before (project constraint that the existing game keeps working; SC1 "never a 404 or a blank page").

</objective>
