## Phase Goal

**As a** player, **I want to** install the game on my phone or computer and get new versions between games, **so that** it opens like an app and an update never ends a game in progress.

This plan expands the proven update and install slices (plans 02-01 and 02-02) to the release side: the owner can pull a broken worker in an emergency, docs-only commits no longer offer players a pointless update, deploys are never cancelled halfway, and CI proves the PWA files are live. It adds no new architecture, so it has no tracer of its own.

<objective>
Rehearse the kill switch once locally and write docs/PWA.md (D-15, D-16); change deploy.yml so docs-only pushes skip the deploy (D-17), deploys queue instead of cancelling (D-18), and every deploy smoke-checks the live manifest, worker and icons (SC5).

Purpose: from the first PWA deploy on, every content phase ships through this worker. The owner needs a tested escape hatch and a deploy pipeline that does not churn update hints or cut a deploy short.
Output: docs/PWA.md (new), .github/workflows/deploy.yml (edited). vite.config.js is flipped and restored during the rehearsal and ends unchanged.
</objective>
