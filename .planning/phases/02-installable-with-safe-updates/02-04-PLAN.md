## Phase Goal

**As a** player, **I want to** install the game on my phone or computer and get new versions between games, **so that** it opens like an app and an update never ends a game in progress.

Release, step 1 of 2: with the owner's go-ahead, build A (every Phase 2 change except the deploy.yml policy commit) goes live, so players can install the game, and the live files are proven under the base path. Step 2 (plan 02-05) releases the deploy.yml commit as build B, which doubles as the first live two-deploy update check.

<objective>
USER STOP A, then push release A to origin/main, watch its deploy, and verify the live manifest, worker, icons and install UI; record the real-device install checks for the end-of-phase UAT.

Purpose: SC1, SC2 and SC5's live clause need the deployed site. The push is a one-way door: it installs sw.js at scope /pilgrims-predestined-path/ and the manifest id /pilgrims-predestined-path/ on every visitor's device, and PROJECT.md requires an explicit go-ahead for release pushes.
Output: origin/main at A; the run URL, step conclusions and live check outputs in SUMMARY. No repository files change.
</objective>
